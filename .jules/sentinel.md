## 2024-05-18 - Client-Side Authorization Bypass via `user_metadata`
**Vulnerability:** The application was using `user.user_metadata.role` as a fallback for `profile.role` to determine the user's effective authorization role. Furthermore, the client explicitly called `supabase.auth.updateUser` with a custom role on sign-up. This allowed a malicious user to trivially craft an API request from the browser assigning themselves the `scout` role or arbitrary permissions bypassing backend RLS checks that relied only on the `profiles` table.
**Learning:** Supabase's `auth.users` metadata can be updated by the client directly via the `updateUser` method. It is inherently untrusted for authorization and should never be used to drive critical logic or UI state.
**Prevention:** Always rely strictly on securely fetched rows from a database table (e.g. `profiles`) that is protected by Row Level Security (RLS) policies. Do not fallback to or trust client-editable metadata fields for authorization logic.
