## 2026-07-03 - Authorization Bypass via Client-Side User Metadata Modification
**Vulnerability:** The application authorized users based on `user.user_metadata.role` as a fallback and allowed the client to arbitrarily update it via `supabase.auth.updateUser`. This allowed any authenticated user to spoof their role (e.g., changing from 'player' to 'scout' or 'admin') and bypass access controls entirely on the client side.
**Learning:** Client-side updates to `user_metadata` are insecure because they happen on the user's device and can be manipulated before reaching the server or directly via the API. Any logic relying on `user_metadata` for authorization can be trivially bypassed.
**Prevention:** Always rely on secure, server-side data models for authorization decisions. Role information should be stored in a protected database table (like a `profiles` table) protected by Row Level Security (RLS), and users should never be able to modify their own role directly via client APIs like `updateUser`.
